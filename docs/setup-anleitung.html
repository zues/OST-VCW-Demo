Apps installieren

ca. 10 Min · von Hand
  1. Claude Desktop App installieren und anmelden (Pro-Abo oder höher).
    https://claude.ai/download
  2. Figma Desktop App installieren und anmelden.
    https://www.figma.com/downloads/
  3. Im Finder einen Ordner anlegen: Dokumente/OST
Warum die Desktop-Apps?
  • Claude Code läuft in der Desktop App im Tab Code und arbeitet direkt in euren Ordnern.
  • Das Figma-Plugin „Desktop Bridge“ läuft nur in Figma Desktop, nicht im Browser.
2

Figma-Datei holen

ca. 3 Min · von Hand
  1. Den Drive-Ordner öffnen und die .fig-Datei herunterladen.
    <Drive-Link: nur in der Lektion bzw. im Artifact, nicht im öffentlichen Repo>
  2. Figma Desktop öffnen → Drafts → Import → Datei wählen.
  3. Datei öffnen und den Link oben aus der Adresszeile kopieren. Ihr braucht ihn in Schritt 4.
Lizenz: Die Datei enthält ein kostenpflichtiges UI-Kit. Nur fürs Seminar verwenden, nicht weitergeben und nicht öffentlich teilen.
3

Projekt holen

ca. 3 Min · Claude
  1. Claude Desktop → Tab Code → Ordner Dokumente/OST wählen.
  2. Prompt senden (Teamname anpassen):
    Prompt
    Klone https://github.com/zues/OST-VC-Base in einen neuen Unterordner teamname. Prüfe danach, ob alles da ist, und sag mir, welchen Ordner ich öffnen soll.
  3. Neue Session starten und den Ordner OST/teamname wählen.
Was heisst „lokal“?
  • Das Projekt liegt nur auf eurem Rechner, Git läuft trotzdem.
  • Jede Person im Team hat eine eigene Kopie. Teilen geht nicht automatisch.
  • Ein Team-Repo könnt ihr später jederzeit noch anlegen.

Eine Person im Team

  1. Claude Desktop → Tab Code → Ordner Dokumente/OST wählen.
  2. Prompt senden (Namen anpassen):
    Prompt
    Klone https://github.com/zues/OST-VC-Base in einen neuen Unterordner teamname.
Erstelle daraus ein privates GitHub-Repo teamname in meinem Account: das Original wird „upstream“, mein Repo „origin“, dann main pushen.
Lade danach diese GitHub-Accounts als Collaborators ein: user1, user2.
Falls ich bei GitHub nicht angemeldet bin oder etwas fehlt, führe mich Schritt für Schritt durch.
  3. Neue Session starten und den Ordner OST/teamname wählen.

Alle anderen

  1. Einladung von GitHub per E-Mail annehmen.
  2. Claude Desktop → Tab Code → Ordner Dokumente/OST wählen.
  3. Prompt senden:
    Prompt
    Klone https://github.com/account/teamname in einen neuen Unterordner teamname. Falls ich bei GitHub nicht angemeldet bin, führe mich durch den Login.
  4. Neue Session starten und den Ordner OST/teamname wählen.
GitHub-Login und Zusammenarbeit
  • Ihr braucht einen GitHub-Account. Claude installiert bei Bedarf das GitHub-Werkzeug gh.
  • Der Login läuft über den Browser: Claude zeigt euch einen Code, den ihr auf github.com bestätigt.
  • Später einfach fragen: „Committe und pushe meine Änderungen“ oder „Hol die neusten Änderungen vom Team“.
  • Nicht gleichzeitig an derselben Datei arbeiten, sonst gibt es Konflikte. Claude hilft beim Auflösen.

Hier braucht Claude euch. Schon im Projekt enthalten, nichts zu tun: shadcn-Skill, Contracts, Seiten-Vorlagen, Dev-Server-Konfiguration.

Figma-Token: Wo und welche Rechte?
  • Figma → Menü oben links → Settings → Security → Personal access tokens → Generate new token.
  • Name: Figma Console MCP, Ablauf: Semesterende.
  • Read: File content, File versions, Library content, Library assets, Current user.
  • Read und Write: Comments. Alles andere: No access.
  • Token kopieren (beginnt mit figd_, wird nur einmal angezeigt) und Claude in den Chat geben.
  • Claude speichert es in eurer Benutzer-Konfiguration, nicht im Projekt.
Plugin „Desktop Bridge“ importieren
  • Figma Desktop → euer File öffnen.
  • Plugins → Development → Import plugin from manifest…
  • Im Dialog ⌘ ⇧ G drücken und eingeben:
~/.figma-console-mcp/plugin/manifest.json
  • Danach Plugins → Development → Figma Desktop Bridge starten und das Fenster offen lassen.
  • Die Datei erscheint erst, wenn Claude die MCP einmal gestartet hat (neue Session).
Was ist die figma-console MCP?
  • Damit kann Claude euer Figma-File lesen und bearbeiten: Frames, Komponenten, Texte, Screenshots.
  • Die Verbindung läuft über das Plugin „Desktop Bridge“ im offenen File.
https://docs.figma-console-mcp.southleft.com/
5

Testen

ca. 2 Min · Claude
  1. Figma Desktop offen, Plugin läuft im File.
  2. Prompt senden:
    Prompt
    Prüfe das Setup: Läuft der Dev-Server, ist Figma verbunden und das richtige File aktiv? Mach einen Screenshot von der ersten Seite im Figma-File und zeig mir die Checkliste.
  3. Alles ✅? Dann seid ihr startklar.
Und danach?
  • Neue Seiten baut ihr nach dem Ablauf in CLAUDE.md: Seiten-Doku → Figma → Contracts → Code → Prüfen.
  • Zum Beispiel: „Leg die Seiten-Doku für die Übersicht an“.

Wenn es hakt

Claude sieht keine Figma-Werkzeuge

Neue Session starten. Die MCP wird nur beim Start einer Session geladen.

Plugin zeigt „MCP scanning“ oder verbindet nicht

Läuft eine Claude-Session in diesem Projekt? Plugin schliessen und neu starten. Dann Claude fragen: „Prüfe die Figma-Verbindung mit figma_diagnose“.

Manifest-Datei nicht gefunden

Claude fragen: „Wo liegt das Desktop Bridge Plugin?“ Claude ermittelt den Pfad.

Fehler 401 oder 403 von Figma

Token falsch oder Rechte fehlen. Neues Token mit den Rechten aus Schritt 4 erstellen und Claude geben.

Seite auf localhost:3000 lädt nicht

Claude fragen: „Starte den Dev-Server neu und zeig mir die Fehlermeldung“.

Irgendwas anderes

/setup erneut senden. Claude prüft jeden Schritt und macht nur, was noch fehlt.
